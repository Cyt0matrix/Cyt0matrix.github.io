Project 1: SIEM Architecture & Windows Telemetry Ingestion

Category: SIEM Engineering & Telemetry Pipeline

Objective

Design and deploy a centralized security monitoring lab from scratch to gain deep technical mastery of SIEM architecture, log ingestion pipelines, and endpoint sensor deployment without relying on automated setup scripts.

Environment & Architecture

  • SIEM Backend: Splunk Enterprise hosted on Ubuntu (`192.168.0.2`).
  • Monitored Endpoint: Windows 11 virtual machine (`192.168.0.3`).
  • Forwarder Agent: Splunk Universal Forwarder shipping telemetry across raw TCP port 9997.
  • Endpoint Sensor: Microsoft Sysmon configured with renderXml=true for granular process and command-line tracking.

Technical Challenge & Resolution

Configuring the Universal Forwarder with the Ubuntu IP inside the deployment server field caused HTTPS connection loops and 502 errors due to port management conflicts between port 8089 (management handshake) and port 9997 (raw data stream).

Solution: Left the deployment server field blank and manually configured receiver routing via local configuration files.

Configuration Artifact (`outputs.conf`)

[tcpout]
defaultGroup = default-rew-server

[tcpout:default-rew-server]
server = 192.168.0.2:9997
