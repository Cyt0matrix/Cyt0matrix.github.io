Project 1: SIEM Architecture & Windows Telemetry Ingestion

Category: SIEM Engineering & Telemetry Pipeline

Objective

Design and deploy a centralized security monitoring lab from scratch to gain deep technical mastery of SIEM architecture, log ingestion pipelines, and endpoint sensor deployment without relying on automated setup scripts.

Environment & Architecture

Built a multi-node virtualized lab environment separating the SIEM backend from the monitored endpoint:

  • SIEM Backend: Splunk Enterprise hosted on Ubuntu (`192.168.0.2`).
  • Monitored Endpoint: Windows 10 virtual machine (`192.168.0.3`).
  • Forwarder Agent: Splunk Universal Forwarder shipping telemetry across raw TCP port 9997.
  • Endpoint Sensor: Microsoft Sysmon configured with renderXml=true for granular process and command-line tracking.

Key Technical Challenges & Resolution

During initial deployment, configuring the Universal Forwarder with the Ubuntu IP inside the Deployment Server field caused HTTPS connection loops and 502 errors. Because the deployment server expects management handshakes over port 8089 while raw data streams over port 9997, this conflict broke the data pipeline.

The Fix: Left the deployment server field blank during installation and manually configured receiver routing via local configuration files (`outputs.conf` and `inputs.conf`), successfully establishing a stable log stream into the `windows_logs` index.

Validation

Confirmed end-to-end ingestion stability by verifying event counts and executing initial validation commands on the Windows endpoint.
